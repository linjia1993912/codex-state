# Codex 刘海用量应用设计方案

- 日期：2026-07-22
- 状态：设计已确认，待用户审阅文档
- 暂定名称：Codex Notch
- 目标平台：macOS 14 及以上
- 分发假设：Developer ID 签名并公证，或开发期本地签名；MVP 不走 Mac App Store

## 1. 产品定位

一款 Codex 专用的原生 macOS 小工具。应用融入 MacBook 物理刘海：平时保持静默，鼠标悬停时快速展示最重要的数据，点击后展开完整统计面板。

产品坚持本地优先：复用用户现有的 Codex CLI 登录，通过 CLI RPC 获取账号与额度，通过本地会话日志统计 Token、估算成本和常用模型。不建设云端服务，不抓取网页，不读取浏览器 Cookie。

## 2. MVP 目标

1. 在带刘海的 MacBook 上自然贴合物理刘海。
2. 无刘海或外接显示器上自动降级为顶部居中胶囊。
3. 根据 Codex 实际返回的数据动态展示额度窗口，不硬编码“5 小时额度”。
4. 展示今日以及最近 1、7、14、30 天的 Token 与估算成本。
5. 展示当前账号、套餐、常用模型和数据更新时间。
6. 全部数据留在本机，空闲时几乎不占用 CPU。

## 3. 明确不做

- 多账号切换。
- Claude、Gemini 等其他 AI 平台。
- 网页抓取、浏览器 Cookie 导入和隐藏 WebView。
- 云同步、云端账户、远程数据库和遥测。
- 任意天数输入；MVP 固定为 1、7、14、30 天。
- 复杂主题系统、插件系统和自动更新模块。
- 把估算成本描述为用户真实支付金额。

## 4. 界面与交互

### 4.1 窗口三态

#### 静默态

- 黑色区域与物理刘海融为一体，不显示数字。
- 建议尺寸约 150 × 30 pt；实际位置根据屏幕刘海区域计算。
- 无刘海屏幕显示顶部居中黑色胶囊。

#### 悬停态

- 鼠标进入后等待 120ms 再展开，降低误触。
- 展开动画约 180ms，使用系统弹性曲线。
- 鼠标离开后等待 250ms 再收起，避免移动到内容区域时闪退。
- 仅显示两项核心数据，不显示账号、图表或设置按钮。

悬停内容按实际能力自适应：

| Codex 返回情况 | 悬停内容 |
| --- | --- |
| 存在短周期与每周额度 | 短周期额度 + 每周额度 |
| 不存在短周期额度，但存在每周额度 | 每周额度 + 今日 Token |
| 不存在任何额度窗口 | 今日 Token + 今日估算成本 |

不存在的额度不保留空卡片，也不使用占位数字。

#### 展开态

- 点击悬停面板后展开并固定。
- 点击外部或按 `Esc` 收起。
- 展开面板建议宽度 368pt，高度根据内容在约 360–430pt 之间变化。
- 系统开启“减少动态效果”时，使用淡入淡出替代弹性形变。

### 4.2 展开面板结构

从上至下保持单列信息流：

1. 账号头部：账号别名、套餐、脱敏邮箱、上次同步时间、刷新和设置。
2. 额度区：只渲染 Codex 实际返回的额度窗口及重置时间。
3. 周期选择：`1 天 / 7 天 / 14 天 / 30 天`，默认 7 天。
4. 汇总区：Token 总量与估算成本。
5. 趋势区：按天展示 Token 柱状趋势。
6. 常用模型：按所选周期内的 Token 占比排序，展示前三名，其余合并为“其他”。

### 4.3 多显示器

- 优先选择存在顶部安全区缺口的显示器。
- 没有带刘海显示器时，使用当前主屏幕顶部居中胶囊。
- 显示器连接、断开或分辨率变化后重新计算位置。
- 全屏应用和不同桌面空间中保持可见，但不抢夺当前应用焦点。

## 5. 技术架构

采用一个原生进程，不引入第三方运行时或 UI 依赖。

MVP 采用非 Mac App Store 分发并关闭 App Sandbox。原因是应用需要启动本机 Codex 子进程并读取 `~/.codex` 已知目录；若以后必须上架 Mac App Store，需要改为用户主动选择 Codex 目录并保存安全作用域书签，这不纳入当前范围。

### 5.1 窗口层

- AppKit `NSPanel`：非激活悬浮窗口，避免点击后切换当前应用。
- SwiftUI：负责静默、悬停、展开三态内容和动画。
- 应用使用 accessory 模式，不显示 Dock 图标。
- 窗口层级使用 `screenSaver`，并启用 `canJoinAllSpaces`、`fullScreenAuxiliary` 等行为；macOS 26 及以上可按系统能力附加 `canJoinAllApplications`。
- 刘海位置由 `NSScreen.safeAreaInsets` 与左右辅助区域推导，不写死具体 MacBook 型号。

### 5.2 状态层

`UsageStore` 是唯一共享状态，负责：

- 维护账号、额度、日统计、常用模型、刷新时间和错误状态。
- 应用启动时刷新一次，此后每 5 分钟刷新额度。
- 用户手动刷新时立即执行。
- 打开完整面板时，若缓存超过 1 分钟则刷新。
- 将原始访问令牌隔离在数据客户端内部，不传入界面状态。

### 5.3 额度与账号

启动本机 Codex `app-server`，通过 JSON-RPC 调用：

- `account/read`：账号标识、邮箱和套餐。
- `account/rateLimits/read`：当前可用的额度窗口、使用比例和重置时间。

界面消费 `QuotaWindow[]`，而不是固定的“5 小时/每周”字段，因此额度机制变化时无需重做界面。

若 Codex 未安装、未登录或 RPC 不可用，应用显示可执行的错误提示，不自动打开浏览器，也不降级到网页抓取。

### 5.4 Token 与成本统计

只读取已知目录：

- `~/.codex/sessions/YYYY/MM/DD/*.jsonl`
- `~/.codex/archived_sessions/*.jsonl`
- 若设置了 `CODEX_HOME`，使用对应目录。

扫描器按行解析事件，按本地日历日期与模型聚合。缓存每个文件的路径、大小、修改时间与聚合结果；后续只重扫新增或变化的文件，不做全盘扫描，也不常驻文件监听。

Token 展示优先使用日志中的权威总量字段。成本按非缓存输入、缓存输入和输出等可获得分类分别估算；若日志只有总量而没有成本所需分类，则保留 Token 并将成本标记为无法估算。

### 5.5 价格表

- 使用应用内置、带更新时间的模型价格表，币种统一为美元。
- 价格表仅用于估算，不代表订阅实际扣费。
- 遇到未知模型时仍统计 Token，成本显示“暂无价格”，并在完整面板给出说明。
- 更新价格表随应用版本发布；MVP 不增加远程配置服务。

## 6. 核心数据结构

```text
UsageSnapshot
├── account: AccountSummary?
├── quotaWindows: [QuotaWindow]
├── dailyUsage: [DailyUsage]
├── selectedRange: 1 | 7 | 14 | 30
├── topModels: [ModelShare]
├── refreshedAt: Date?
├── isStale: Bool
└── warnings: [UsageWarning]
```

`DailyUsage` 至少包含日期、输入 Token、缓存输入 Token、输出 Token、总 Token、估算成本和按模型拆分的数据。

## 7. 隐私与安全

- 默认脱敏邮箱，仅在设置页允许查看完整邮箱。
- 不在日志、错误消息、缓存或 SwiftUI 状态中保存访问令牌。
- 不上传本地会话内容，只读取 Token 计数、模型和时间字段。
- 忽略会话里的提示词、回复正文和文件内容。
- 缓存仅保存聚合数字与文件指纹，不复制原始会话。
- 应用不要求完全磁盘访问；若用户把 `CODEX_HOME` 放在受保护位置，则明确提示权限问题。

## 8. 错误与降级

| 场景 | 行为 |
| --- | --- |
| Codex 未安装 | 显示“未找到 Codex CLI”和安装说明 |
| Codex 未登录 | 显示“请先登录 Codex”，不自动启动认证 |
| 网络或 RPC 失败 | 保留上次成功数据，标记“数据已过期” |
| 部分 JSONL 损坏 | 跳过无效记录，保留其余统计并显示扫描警告 |
| 未知模型价格 | 展示 Token，成本显示“暂无价格” |
| 无额度窗口 | 隐藏额度区，悬停展示今日 Token 与估算成本 |
| 显示器断开 | 将面板移动到当前主屏幕顶部 |

## 9. 性能策略

- 不使用 WebView，不做网页轮询。
- 额度默认每 5 分钟刷新一次，不提供更短周期。
- 会话日志使用文件级增量缓存。
- 图表直接使用 SwiftUI `Shape` 绘制，不引入图表依赖。
- 面板收起时停止非必要动画。
- 睡眠唤醒后执行一次合并刷新，不补跑离线期间的定时任务。

## 10. 可访问性

- 所有百分比、Token 和按钮提供 VoiceOver 标签。
- 颜色不是唯一状态提示，同时显示文字与数值。
- 支持系统“减少动态效果”和“增强对比度”。
- `Esc` 可关闭面板；固定快捷键 `⌥⌘U` 可切换完整面板，保证不依赖鼠标悬停。

## 11. 测试与验收

### 自动化检查

1. 有短周期额度、只有每周额度、完全无额度三种快照均正确布局。
2. JSONL 正常行、未知事件、损坏行和截断末行均不会导致扫描失败。
3. 跨日、夏令时与系统时区变化后，日统计归属正确。
4. 已知模型成本计算正确；未知模型不会被计算为零成本。
5. 文件未变化时复用缓存，文件变化时只重算对应文件。
6. 邮箱脱敏和访问令牌隔离有效。

### 手工验收

1. 带刘海 MacBook 上静默态与物理刘海对齐。
2. 无刘海屏幕显示顶部居中胶囊。
3. 全屏应用、多个桌面空间和外接显示器切换时位置正确。
4. 悬停、点击固定、点击外部和 `Esc` 的状态转换稳定，无闪烁。
5. 睡眠唤醒、网络断开和 Codex 退出后不会卡死或丢失最后一次有效数据。
6. VoiceOver、减少动态效果和键盘快捷键可用。

## 12. 验收口径

MVP 完成的标准是：用户已安装并登录 Codex 后，无需再次登录即可在刘海查看真实存在的额度窗口、今日 Token，并在展开面板查看 1、7、14、30 天 Token、估算成本、账号和常用模型；额度机制变化或短周期额度消失时，界面能自动调整且不显示错误占位。
